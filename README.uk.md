# grid_plug — скрипт керування реле Shelly за наявністю мережі та рівнем заряду батареї (Victron GX)

**grid_plug by [mixtoolabs](https://github.com/mixtoolabs)** · Ліцензія: [Apache 2.0](LICENSE) · [English](README.md)

Скрипт для Shelly, який вмикає і вимикає реле пристрою Shelly Gen2+ (розумної розетки або
реле) за **наявністю мережі** та **рівнем заряду батареї (SOC)** системи Victron Energy.
Усі дані скрипт бере з MQTT-брокера GX-пристрою Victron у вашій локальній мережі — без
хмари і без налаштувань у коді.

Типове застосування: живити навантаження від мережі лише тоді, коли мережа є і батарея вже
достатньо заряджена, і миттєво вимикати його, коли мережа зникає.

---

## Як це працює

| Умова | Реле |
|---|---|
| Мережі немає (Multi/Quattro інвертує, або даних немає) | **вимкнене одразу** |
| SOC батареї невідомий (немає значення, немає даних 65 с) | **вимкнене** |
| Мережа є і SOC ≥ порога | **увімкнене** |
| Мережа є і SOC ≤ поріг − 2 % | **вимкнене** |
| SOC між цими межами | зберігає попередній стан (гістерезис, реле не клацає) |
| Старт скрипта, розрив MQTT | **вимкнене** (безпечний стан) |

- **Без налаштувань.** Скрипт сам знаходить portal ID GX-пристрою та instance
  Multi/Quattro (VE.Bus) з MQTT-тем. Вам потрібно лише вказати в налаштуваннях Shelly IP адресу MQTT-брокера GX.
- **Єдине налаштування — повзунок «On at SOC»** (50…100 %, крок 5 %, типово 95 %). Скрипт
  створює його при першому запуску, значення зберігається після перезавантаження.
- **Наявність мережі** — `vebus/<instance>/Ac/ActiveIn/ActiveInput`: активний вхід AC-in-1
  або AC-in-2 — «мережа є», «inverting» — «мережі немає».
- **SOC батареї** — `system/0/Dc/Battery/Soc` (головна батарея системи).
- **Безпечне увімкнення живлення.** Скрипт ставить реле стан при увімкненні живлення
  «вимкнено», тож після зникнення живлення реле лишається вимкненим, доки скрипт не
  ухвалить рішення.
- **Keep-alive.** Скрипт кожні 30 с надсилає GX MQTT keep-alive, щоб GX продовжував
  публікувати значення.
- **Відновлення зв'язку.** Після розриву MQTT скрипт використовує вже знайдені portal ID
  та instance і не шукає їх заново.

## Вимоги

- **Shelly Gen2 або новіший з реле** (розумна розетка або реле), прошивка **1.5 або
  новіша**.
- **Система Victron Energy** з GX-пристроєм (Cerbo GX, Venus OS) та інвертором-зарядним
  **Multi/Quattro (VE.Bus)** в **одній локальній мережі** з Shelly.
- **Увімкнений MQTT-доступ на GX.** У поточному інтерфейсі Venus OS:
  **Settings → Integrations → MQTT Access** (розділ «Server applications»).
  GX попереджає: *«A Security Profile must be configured before the network services can be
  enabled, see Settings - General»* — спершу задайте профіль безпеки в Settings → General.

### Сумісність

| Пристрій | Стан |
|---|---|
| Shelly Plug M Gen3, прошивка 2.1.0 | **перевірено автором** |
| Ogemray 25A by Shelly (SW40 PbS) firmware 1.5.0-ogemray25prod1-g5ae3a20 | **перевірено автором** |
| Інші Shelly Gen2+ з реле | мають працювати (автором не перевірено) |

Зауваги:

- **Повзунок «On at SOC» — віртуальний компонент.** За документацією Shelly віртуальні
  компоненти є на пристроях **Gen2 Pro, Gen3, Gen4**.
  На пристроях **без віртуальних компонентів** скрипт теж працює, але з **фіксованим
  порогом 95 %**.
- Керується лише **перший канал реле** (`switch:0`).
- Не підтримуються: Multi RS, окремі зарядні пристрої без даних про вхід мережі.

## Встановлення

### 1. Увімкніть MQTT на GX Victron

На GX: **Settings → Integrations → MQTT Access** → увімкнути.
Запам'ятайте IP-адресу GX у вашій локальній мережі.

### 2. Під'єднайте Shelly до MQTT-брокера GX

У вебінтерфейсі Shelly (відкрийте IP-адресу Shelly в браузері):
**Settings → MQTT**.

| Поле | Значення |
|---|---|
| **Enable** | **увімкнено** (обов'язково) |
| Connection type | No TLS |
| **Server** | **`<IP вашого GX>:1883`** (обов'язково) |
| Username / Password | порожні |
| Enable 'MQTT Control', Enable RPC over MQTT, RPC status notifications over MQTT, Generic status update over MQTT | **скрипт їх не використовує** — необов'язкові; можна вимкнути, щоб зменшити кількість повідомлень на брокері GX |

Натисніть **Save**. Якщо Shelly попросить перезавантаження — перезавантажте.

### 3. Встановіть скрипт

1. У вебінтерфейсі Shelly відкрийте **Scripts** → **Create script**.
2. Дайте назву, наприклад `grid_plug`.
3. Вставте весь вміст [`grid_plug.js`](grid_plug.js) і натисніть **Save**.
4. Увімкніть для скрипта **Run on startup** (запуск при старті).
5. Натисніть **Start**.

### 4. Перевірте, що скрипт працює

Відкрийте **консоль** скрипта. Приблизно за хвилину мають з'явитися рядки на кшталт
цих (порядок деяких рядків може відрізнятися):

```
[grid_plug] start 5.2
[grid_plug] threshold 95
[grid_plug] creating number:200 On at SOC
[grid_plug] discovering portal id
[grid_plug] number:200 created {"id":200}
[grid_plug] portal id <ваш portal id>
[grid_plug] vebus instance <instance>
[grid_plug] grid present (ActiveInput=0, AC-in-1)
[grid_plug] soc topic N/<ваш portal id>/system/0/Dc/Battery/Soc
[grid_plug] soc 96 (threshold 95)
[grid_plug] relay -> ON
```

## Налаштування порога

В додатку Shelly Cloud відкрийте **Components** → **On at SOC** і пересуньте повзунок
(50…100 %). Повзунок доступний лише в застосунку Shelly Cloud, у вебінтерфейсі пристрою
його немає. Зміна діє одразу:

- реле **вмикається**, коли SOC досягає порога;
- реле **вимикається**, коли SOC опускається до **поріг − 2 %** (для 95 % — на 93 %).

## Повідомлення в консолі

| Повідомлення | Значення |
|---|---|
| `start 5.2` | скрипт запущено (версія) |
| `waiting for MQTT` | Shelly ще не під'єднаний до брокера GX |
| `discovering portal id` / `portal id …` | пошук / знайдено GX |
| `vebus instance …` | знайдено Multi/Quattro |
| `grid present (ActiveInput=0, AC-in-1)` | мережа є на вході 1 |
| `grid absent (ActiveInput=240, inverting)` | мережі немає, Multi інвертує |
| `soc 95.5 (threshold 95)` | SOC батареї і поточний поріг |
| `threshold 75` | повзунок пересунуто |
| `relay -> ON` / `relay -> OFF` | команда реле |
| `soc unknown (no data)` / `grid absent (no data)` | від GX немає даних 65 с |
| `MQTT disconnected` / `MQTT connected` / `resume portal id …` | зв'язок втрачено і відновлено |
| `initial_state "on" -> off` | стан реле при увімкненні живлення змінено на «вимкнено» |

## Що лишається на пристрої після видалення скрипта

- Віртуальний компонент **«On at SOC»** (`number:200`) — видаліть його вручну в
  **Components**.
- Стан реле при увімкненні живлення лишається **«Turn OFF»** (налаштування виходу →
  «Action on power on») — за потреби поверніть як було.
